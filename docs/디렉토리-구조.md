# 디렉토리 구조

기능(feature)과 관심사(layer)를 기준으로 나눠, 어디에 무엇이 있는지 예측 가능하도록 구성했습니다.

## 전체

```
study-calendar/
├── backend/                  # FastAPI 백엔드
├── frontend/                 # React 프론트엔드
├── monitoring/               # 모니터링 스택 설정
├── docs/                     # 학습·설계 문서
├── docker-compose.yml            # 앱(3-tier: db + backend + frontend)
├── docker-compose.monitoring.yml # 모니터링 스택(선택)
├── .env.example
└── .gitignore
```

## 백엔드 (`backend/`)

계층별로 분리했습니다. 요청은 `api(라우터) → schemas(검증) → models(DB)` 흐름을 따릅니다.

```
backend/
├── app/
│   ├── core/            # 설정·보안
│   │   ├── config.py    # 환경변수 기반 설정 (SECRET_KEY 등)
│   │   └── security.py  # 비밀번호 해싱(bcrypt), JWT 발급/검증
│   ├── db/
│   │   ├── base.py      # SQLAlchemy Base
│   │   └── session.py   # 엔진·세션(get_db)
│   ├── models/          # SQLAlchemy 모델(테이블)
│   │   ├── user.py      # User(role 포함)
│   │   ├── study.py     # Subject(계층), StudySession
│   │   ├── schedule.py  # ScheduleItem
│   │   └── routine.py   # RoutineDefinition/Version/Completion
│   ├── schemas/         # Pydantic 스키마(요청/응답 검증)
│   │   ├── auth.py, study.py, schedule.py, routine.py, analytics.py
│   ├── api/
│   │   ├── deps.py      # 인증 의존성(get_current_user, get_current_admin)
│   │   └── routes/      # 엔드포인트
│   │       ├── auth.py, subjects.py, sessions.py, schedules.py
│   │       ├── routines.py, analytics.py, admin.py
│   │       └── __init__.py  # api_router로 통합
│   ├── content/
│   │   └── learning_guides.py  # 관리자 학습 가이드 데이터
│   └── main.py          # 앱 진입점, CORS, /metrics, /health
├── scripts/
│   └── make_admin.py    # 사용자 관리자 승격 CLI
├── requirements.txt
├── Dockerfile
└── .dockerignore
```

## 프론트엔드 (`frontend/`)

feature 단위로 로직을 모으고, 공용 UI는 `components`, 순수 함수는 `lib`로 분리했습니다.

```
frontend/
├── src/
│   ├── api/             # axios 클라이언트 + 엔드포인트별 함수
│   │   ├── client.js    # baseURL, JWT 인터셉터, 401 처리, tokenStorage
│   │   ├── auth.js, subjects.js, sessions.js, schedules.js
│   │   ├── routines.js, analytics.js, admin.js
│   ├── auth/
│   │   └── AuthContext.jsx  # 로그인 상태, user(role 포함)
│   ├── components/      # 공용 컴포넌트
│   │   ├── Layout.jsx       # 상단 네비(브랜드 Study → index)
│   │   ├── ProtectedRoute.jsx, AdminRoute.jsx
│   │   ├── CalendarGrid.jsx, CalendarHeader.jsx  # 캘린더 공용
│   │   └── ProgressBar.jsx, ProgressRing.jsx     # 진행률 공용
│   ├── features/        # 기능 단위
│   │   ├── timer/       # useStudyTimer 훅
│   │   ├── subjects/    # SubjectSelect, SubjectManager
│   │   ├── study/       # StudyRecordForm
│   │   └── dashboard/   # MonthlyBarChart, SubjectBreakdown
│   ├── lib/             # 순수 유틸
│   │   ├── time.js          # 시간/날짜 포맷, 달력 그리드
│   │   ├── progress.js      # 진행률 색상/라벨
│   │   └── useMonthNavigation.js
│   ├── pages/           # 라우트 페이지
│   │   ├── DashboardPage.jsx (index)
│   │   ├── TimerPage.jsx, SchedulePage.jsx, StudyPage.jsx
│   │   ├── GuidesPage.jsx (관리자)
│   │   └── LoginPage.jsx, RegisterPage.jsx
│   ├── styles/index.css
│   ├── App.jsx          # 라우팅
│   └── main.jsx         # 진입점
├── package.json
├── vite.config.js       # /api 프록시
├── nginx.conf           # 배포 시 정적 서빙 + /api 프록시
├── Dockerfile
└── .dockerignore
```

## 설계 원칙

- **계층 분리**: 라우터는 얇게, 검증은 스키마, 데이터는 모델. 테스트·변경이 쉬움.
- **공용 컴포넌트/유틸 재사용**: ProgressBar/ProgressRing, CalendarHeader 등을 여러 페이지가 공유.
- **feature 폴더**: 타이머·과목·대시보드처럼 응집도 높은 로직을 한곳에 모음.
